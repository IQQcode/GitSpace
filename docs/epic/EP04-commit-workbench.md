> 目标：把单仓提交做到 Fork 的顺手程度：块与行粒度、丢弃可撤销、提交信息随手可取、一键提交并推送。跨仓一次提交见 EP05-F06。

## 1. 现状

- 未暂存 / 已暂存两栏，文件级与块级暂存，管线为 `git diff` 拆块后 `git apply --cached`，与 `git add -p` 等价（26 条等价性测试覆盖）。
- 丢弃只有文件粒度：工作区改动、暂存加工作区、未跟踪文件三种范围（`DiscardScope`）；未跟踪文件用 `FileManager.removeItem` 直接删除，不可恢复；没有单块丢弃、全部丢弃、撤销。
- 提交信息只有输入框与 amend，没有历史、上次信息、模板；钩子失败原样展示输出。
- 没有「提交并推送」，没有行级暂存，文件列表为平铺。

## 2. 对标参考

- Fork：逐行暂存与取消暂存；最近提交信息；丢弃块后不重置滚动位置；partial stash；.gitignore 模板（2.65）；⌥⌘↩ Commit & Push；AI 生成提交信息（2.59 Claude、2.64 Codex、2.70 Cursor）。
- IDEA：提交信息历史，读取 `commit.template`；Amend 可选目标提交；Author、Sign-off；Commit and Push（⌥⌘K）；「Split Chunks and Include Selected Lines into Commit」做行级；Changelist 把改动按逻辑分组。

## 4. 交互规格

### 4.1 提交区（F02、F03、F04、F08）

```text
+-- 提交到 GdThread（feature/TASK-123456） ---------------------------------+
| [TASK-123456] 话题卡曝光埋点修正                       标题 28 / 50   [v] |
|                                                                          |
| 修复进吧后话题卡重复曝光的问题。                                         |
+--------------------------------------------------------------------------+
| [ ] Amend   [ ] Sign-off   作者 [默认 v]        AI 草稿（未开启）        |
|                                     [提交 ⌘↩]   [提交并推送 ⌥⌘↩]        |
+--------------------------------------------------------------------------+
```

- [v] 历史下拉：本仓最近 20 条提交标题，加上在 GitSpace 里输入过但没提交成功的信息；选中后整段替换。
- 钩子失败、提交被取消时，输入的信息保留到下次打开（MRD 10.6「钩子失败：工作区保持改动」）。
- 存在 `commit.template` 时，空输入框显示模板内容作为初始文本。
- 分支名含卡片号（正则在设置中配置，默认 `[A-Z]+-\d+`）时，空输入框自动带入 `[TASK-123456] ` 前缀（F04）。
- 标题超过 50 字符变色提示，超过 72 字符给出警告，不阻止提交。
- 「提交并推送」：提交成功后直接打开推送确认（EP05-F02 / F05）；Gerrit 仓按 EP08-F02 推送到评审。

### 4.2 丢弃与撤销（F01）

- 单块：块标题栏「丢弃此块」，二次确认后对工作区反向应用该块。
- 全部：工具栏「丢弃全部改动」，确认框列出将受影响的文件数与未跟踪文件数。
- 快照：每次丢弃前执行 `git stash create` 记录工作区状态（不改动工作区与任何 ref），快照 SHA 写入操作日志。
- 撤销：丢弃完成后的通知条提供「撤销」，按文件执行 `git restore --source=<快照> --worktree -- <path>`；未跟踪文件从废纸篓恢复。
- 撤销窗口：本次会话内且 24 小时内有效，超出后快照可能被 `git gc` 回收。窗口长度待评审。

| 状态 | 表现 |
|---|---|
| 丢弃成功 | 通知「已丢弃 3 个文件的改动 [撤销]」，列表保持当前滚动位置 |
| 撤销时文件已被再次修改 | 拒绝覆盖，提示「文件已变化，请手动处理」并给出快照 SHA |
| 未跟踪文件移入废纸篓失败 | 不删除，提示原因 |

### 4.3 行级暂存（F05）

- 在 diff 中按住拖选或逐行勾选，块标题栏出现「暂存选中行 / 取消暂存选中行」。
- 实现沿用现有管线：按选中行重写补丁后 `git apply --cached`，补丁应用失败视为索引陈旧，重新取 diff 并提示刷新（TechStack §5.3）。
- 操作后列表与 diff 保持原滚动位置与选中文件。

### 4.4 AI 草稿（F09）

- 默认关闭。开启时说明：暂存区 diff 会发送给你在设置中配置的本机 agent CLI（EP09-F06），由该工具决定数据去向。
- 生成结果作为草稿显示在输入框上方，点「采用」才写入；生成失败不影响提交。
- 不在任何时候自动提交。

### 4.5 变更分组（F10）

- 分组是 GitSpace 工作区里的标签，不写入 git：一个分组可以包含多个仓库的文件（以文件为粒度）。
- 分组可「一起提交」（走 EP05-F06 跨仓提交，信息默认取分组名）或「一起 stash」（走 EP05-F11）。
- 与 IDEA Changelist 的区别：IDEA 的 Changelist 针对单个项目，GitSpace 的分组天然跨仓。

## 5. 验收口径

1. 单块丢弃后工作区内容与在命令行对同一块执行 `git checkout -p`（选该块）的结果一致。
2. 撤销丢弃后文件内容哈希与丢弃前一致。
3. 行级暂存后 `git diff --cached` 与 `git add -p` 中手工编辑同样行的结果一致。
4. 提交后 HEAD 前进 1 个提交且工作区干净；amend 后父提交不变（MRD 10.4-10）。
5. 钩子失败时不产生提交，信息保留，原始输出完整展示。
6. AI 未开启时，没有任何进程调用或网络请求与 AI 相关。

## 6. 风险与明确不做

- 不提供 `--no-verify` 跳过钩子的开关（MRD 10.2-C 要求钩子不吞错）；是否开放列为待评审。
- AI 只接本机工具，不内置任何云端服务，也不在 GitSpace 里保存 API key。
