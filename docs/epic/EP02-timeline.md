> 目标：把时间线从「按时间排好的提交列表」升级为能看清分支拓扑、能从任一提交出发完成后续动作的主工作区。

## 1. 现状

- 数据：每仓 `git log --all --date-order`，默认近 90 天、每仓最多 800 条，内存合并排序（`GitRepository.commits`、`TimelineModel.perRepoLimit`）。
- 过滤：单选仓库、分支、作者、时间范围、关键字（信息或 hash）；没有路径过滤与多选。
- 提交图：每行一个仓库色点，没有分支与合并曲线（Story-1029 偏离项 4）。
- 行内信息：标题、作者头像、短 SHA、相对时间、仓库名与分支文本；分支名以纯文本截断显示，没有 ref 徽标。
- 详情：标题、作者、时间、Change-Id、文件列表与增删行数、原始 unified diff；合并提交只按第一父提交展示。
- 交互：提交行没有右键菜单，只能复制完整 hash。

## 2. 对标参考

- IDEA Log：多 root 用左侧色条区分；按分支、收藏分支、作者、日期、root 与目录过滤；文本、hash、正则搜索；⌘F 跳到 hash / 分支 / tag；← / → 跳父子提交；可把一组过滤开成新标签；选两条提交 Compare Versions；Show Repository at Revision。
- Fork：多彩提交图，分支标签按图颜色绘制（2.53），双击标签检出（2.16）；有正文的提交显示「↩︎」（2.55）；空格弹出详情（2.67）；按 diff 内容与文件路径搜索；只看当前分支（⇧⌘A）；stash 直接显示在提交列表。

## 4. 交互规格

### 4.1 时间线行结构（F01、F02）

```text
图列        Ref 徽标                       标题                        作者  短 SHA   时间   仓库
| * o      [HEAD -> feature/TASK-123456]  TASK-123456 话题卡曝光 ↩︎    jia   a1b2c3d  2 小时  GdThread
| |/       [origin/master] [v22.14.0]     Merge "TASK-123300 ..."       wang  9f8e7d6  5 小时  GdThread
  o                                         TASK-123456 补充单测          jia   d4e5f6a  昨天    GdFeedSupports
```

- 图模式自适应：过滤到 1 至 3 个仓库时画完整 DAG；超过 3 个仓库时默认紧凑模式（仓库色点 + 合并标记），视图选项可手动切换。阈值待评审。
- lane 布局在加载时后台预计算，滚动时不做布局计算（TechStack §4.3）。
- 有正文的提交在标题后显示「↩︎」；鼠标悬停显示完整信息。
- 双击分支徽标检出该分支；工作区有改动时走 EP06-F03 的智能切换。

### 4.2 右键菜单（F03）

```text
复制 SHA                  ⌘C
复制提交信息
复制链接（Gerrit / Web）
---------------------------
检出此提交（detached）
从此新建分支...
在此打 tag...             （EP07-F10）
---------------------------
与工作区比较              （F06）
与另一条提交比较           （选中两条时出现）
---------------------------
Cherry-pick 到当前分支     （EP06-F05）
回滚此提交 Revert          （EP06-F07）
重置当前分支到此...        （EP06-F08）
从此交互式变基...          （EP06-F10）
---------------------------
在浏览器打开 / 打开卡片    （EP09-F03 / F04）
```

- 多选提交时，菜单只保留对多选有意义的动作（复制、cherry-pick 多个、比较两条）。
- 跨仓多选时，比较类动作置灰并提示「只能比较同一仓库的提交」。

### 4.3 提交详情（F04）

- 头部：仓库、完整 SHA（可复制）、author 与 committer（不同才显示 committer）、author 时间与 commit 时间。
- 正文：完整信息，trailer（`Change-Id`、`Signed-off-by`）单独成行，卡片号与 Change-Id 渲染为链接（EP09-F03、EP08-F06）。
- 父提交：短 SHA 列表，点击在时间线定位。
- 「包含于」：点击后加载 `git branch -a --contains` 与 `git tag --contains`，避免每次选中都执行。
- 文件列表与 diff 渲染由 EP03 负责。

### 4.4 过滤与导航（F05、F07）

- 过滤条：仓库（多选，可「只看有改动的仓」）、分支（可「只看当前分支」）、作者（多选）、时间、路径（文件或目录）、关键字（信息 / hash，可切换正则与大小写）。
- ⌘L 聚焦关键字框；⌘F 弹出跳转框，输入 hash、分支或 tag 后定位。
- ← / → 在当前提交的父 / 子提交间跳转，跨仓混排时只在同仓内跳。
- 「保存为视图」把当前过滤保存为命名视图，出现在时间线 tab 的下拉里。

| 状态 | 表现 |
|---|---|
| 过滤无结果 | 「没有匹配的提交」+「重置过滤」（MRD 10.6） |
| 命中已截断区间之外 | 提示「当前只加载近 90 天」+「加载更早 3 个月 / 全部」（F09） |
| 仓库读取失败 | 该仓在过滤器中标红，其余仓正常显示（MRD 10.4-7） |

## 5. 验收口径

1. 单仓完整图模式下，每条提交的父子连线与 `git log --graph --all --format=%H %P` 一致。
2. Ref 徽标与 `git for-each-ref` 的结果一致，HEAD 指向正确。
3. 「包含于」列表与 `git branch -a --contains <sha>`、`git tag --contains <sha>` 一致。
4. 两提交对比的文件列表与 `git diff --name-status A B` 一致。
5. 路径过滤结果与 `git log --all -- <path>` 在时间窗内一致。
6. 50 仓 × 10 万提交下，过滤响应 ≤300ms、滚动 ≥55fps（MRD 10.4-2，依赖 EP12-F06）。

## 6. 风险与明确不做

- 多仓完整 DAG 的 lane 数量随仓库数增长，紧凑模式是默认值；完整图只在少量仓时提供。
- 统计类视图只用本地数据，不上传（MRD §12）。
