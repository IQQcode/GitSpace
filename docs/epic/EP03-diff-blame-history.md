> 目标：让「看改动」达到 Fork / IDEA 的日常水准：并排对照、行号与词级高亮、blame、文件历史、图片 diff。

## 1. 现状

- 提交详情与提交视图都用 `DiffTextView` 渲染原始 unified diff 文本，`diff --git`、`index` 等头部行直接显示。
- 没有并排视图、行号、词级高亮、语法高亮（Story-1029 偏离项 5）。
- 引擎没有 blame、`log --follow` 等接口，界面没有 blame 与文件历史入口。
- 未跟踪文件以读取文件内容的方式伪造 diff 预览；二进制与图片没有专门处理。

## 2. 对标参考

- IDEA Diff viewer：Side-by-side / Unified；忽略空白五档；高亮粒度 Words / Lines / Split chars；对齐改动、同步滚动、折叠未改动；F7 / ⇧F7 跳转。Annotate with Git Blame 与 Annotate previous revision；Show History 支持文件、目录、选区。
- Fork：并排 diff，行内高亮，显示隐藏字符（1.0.77），⌘↑ / ⌘↓ 上下块（2.67），diff 内搜索；blame 带时间线（2.10）与前进后退（2.11）；文件与目录历史，选中代码的历史（2.59）；图片 diff 有并排、swipe、onion skin、像素差异（2.12、2.42）。

## 4. 交互规格

### 4.1 diff 视图（F01、F02、F05）

```text
+-- Sources/Feed/FeedModel.m   +12 -3   [统一 | 并排]  忽略空白 [无 v]  上下文 [3 v]  [...] --+
|  旧                                  |  新                                              |
|  41  if (item.layoutType ==          |  41  if (item.layoutType ==                       |
|  42 -    kHotTopic) {                |  42 +    kHotTopic || kDailyTopic) {              |
|  43      break;                      |  43      break;                                   |
|  ...  折叠 120 行未改动  [展开]       |                                                   |
+-------------------------------------------------------------------------------------------+
| 第 2 / 5 处改动        ⌘↑ 上一处   ⌘↓ 下一处   ⌘F 搜索                                     |
+-------------------------------------------------------------------------------------------+
```

- 文件标题栏取代原始 diff 头：显示路径、重命名前后路径、增删行数、文件模式变化。
- 词级高亮只标出行内真正改动的词；整行新增或删除时不做词级高亮。
- 并排模式两栏同步滚动；只有一侧有内容的行用空白填充对齐。
- 「...」菜单：复制为补丁（EP07-F11）、在编辑器打开当前行（EP09-F01）、用外部 diff 工具打开（EP09-F02）。
- 提交视图中的块级暂存、丢弃按钮在两种模式下都可用；并排模式下按钮放在两栏之间的分隔条上。

### 4.2 Blame（F03）

入口：文件行右键「Blame」；提交详情文件列表右键；文件历史中选中版本后「Blame 此版本」。

```text
+-- Blame：GdThread / Sources/Thread/ThreadCell.m @ HEAD ----------------- [< 后退] [前进 >] --+
| a1b2c3d  jia    2 天前   |  101  - (void)layoutSubviews {                                    |
|                          |  102      [super layoutSubviews];                                 |
| 9f8e7d6  wang   3 个月前 |  103      self.titleLabel.frame = ...                             |
+-----------------------------------------------------------------------------------------------+
```

- 同一提交的连续行只在第一行显示信息；左侧色块越新越深。
- 悬停显示完整提交信息；点击跳到统一时间线并选中该提交。
- 右键某一行「Blame 上一版本」，切到 `<sha>^` 继续追溯；后退 / 前进记录追溯路径。

### 4.3 文件历史（F04）

- 左栏：修改过此文件的提交（重命名前的历史也在内），显示时间、作者、标题；右栏：该提交对此文件的 diff。
- 右键：与当前版本比较；取回此版本（写入工作区前二次确认，等价 `git restore --source=<sha> -- <path>`）；Blame 此版本。
- 目录历史：在文件树或路径过滤中选目录，列出触及该目录的提交。

### 4.4 图片 diff（F07）

- 模式：并排、swipe（拖动分界线）、onion skin（透明度滑块）、像素差异（高亮不同像素）。
- 显示尺寸与文件大小变化；LFS 指针文件按 EP10-F04 的规则处理。

| 场景 | 表现 |
|---|---|
| 文件超过 5000 行改动 | 分块渲染，显示「继续加载」；阈值在 M0 实测后定 |
| 二进制非图片 | 显示「二进制文件，大小 12KB → 18KB」与「用外部工具打开」 |
| 重命名且有改动 | 标题栏显示「旧路径 → 新路径」与相似度 |
| 仅权限变化 | 显示「文件模式 100644 → 100755」 |

## 5. 验收口径

1. 并排与统一视图展示的改动行与 `git diff` 输出逐行一致，不丢行、不重复。
2. 忽略空白选项的结果分别与 `git diff`、`git diff --ignore-space-at-eol`、`git diff -w`、`git diff --ignore-blank-lines` 一致。
3. Blame 每行的提交与 `git blame --porcelain <rev> -- <path>` 一致。
4. 文件历史列表与 `git log --follow --format=%H -- <path>` 一致。
5. 取回旧版本后文件内容哈希与 `git show <sha>:<path>` 一致。
6. 万行级 diff 打开与滚动不卡顿（TechStack §14 的分块阈值以 M0 实测为准）。

## 6. 风险与明确不做

- diff 只读展示与块 / 行暂存，不做编辑器式的就地修改（IDEA 允许在 diff 中直接编辑本地版本，本期不做）。
- 语法高亮的语法包逐个核查许可（TechStack §11）。
