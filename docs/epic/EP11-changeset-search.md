> 目标：把 Story-1030 中作为超前占位的「变更集」「聚合检索」补到 MRD P1 / P2 的完整口径，并与 cherry-pick、评审推送、跨仓 tag 打通。

## 1. 现状

- 变更集：从时间线已加载的提交里用正则提取卡片号分组，展示涉及仓、提交数、作者数，可复制交付清单、跳转时间线。
- 聚合检索：对关键字做统一匹配，结果按仓分组，可复制 CR 清单。
- 两者的数据都来自时间线的内存数据，只覆盖近 90 天、每仓最多 800 条；超出窗口的提交查不到。
- 是否保留为一级 tab 仍是 Story-1030 的待评审项。

## 3. 交互规格

```text
+-- 变更集：TASK-123456 话题卡曝光 ------------------------- [挑到分支...] [推送评审] [复制清单] --+
| 仓库             提交   已推送   已进入 release/22.14   change                                |
| GdThread         2      是       否                    12345（已推送评审）                     |
| GdFeedSupports   1      是       是                    12346                                   |
| GdHome           无     期望涉及，未找到提交  [忽略]                                            |
+-----------------------------------------------------------------------------------------------+
```

- 「已进入目标分支」用 `git branch -r --contains <sha>` 或 patch-id 比对判断，目标分支在变更集顶部选择。
- 检索框支持字段前缀：`card:TASK-123456 author:jia path:Sources/Feed`；不带前缀时匹配信息与 SHA。
- 交付清单模板变量：`{repo}` `{sha}` `{subject}` `{author}` `{changeUrl}` `{cardUrl}`。

## 4. 验收口径

1. 卡片号检索结果与对每个仓执行 `git log --all --grep=<卡片号>` 的并集一致（接入索引后不受时间窗限制）。
2. 路径检索与 `git log --all -- <path>` 一致。
3. 「已进入目标分支」与 `git branch -r --contains <sha>` 一致。
4. 交付清单中的 SHA、标题、链接与数据源一致。

## 5. 风险与待评审

- 时间窗内存数据会漏掉早期提交，F01 与 F03 应在 EP12-F06 索引上线后再交付，否则结果不完整。
- 一级入口：建议保留「变更集」为一级 tab（锚点团队按卡片交付），「聚合检索」并入时间线的过滤条与 ⌘K；需评审确认。
