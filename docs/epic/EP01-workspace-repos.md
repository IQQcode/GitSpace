# EP01 多工作区与仓库管理

> 目标：让 50+ 仓的工程能按工作区、窗口、标签页组织起来，并补齐 remote 与凭据的管理入口。

## 1. 现状

- 只有单工作区，标题栏工作区 pill 的下拉是占位（`docs/func/GitSpace-Features-v1.0.md` §10）。
- 只有一个 `WindowGroup`，代码中没有 `openWindow`，不存在多窗口或标签页。
- 纳管入口齐全：添加仓库、扫描父目录（深度 3）、粘贴 mgit 清单，配置以 JSON 持久化。
- 鉴权失败只在批量结果里显示错误文本，代码中没有 Keychain 或凭据配置入口；git 运行时设置了 `GIT_TERMINAL_PROMPT=0`，缺凭据时直接失败。
- 没有 remote 管理、克隆、仓库分组。

## 2. 对标参考

- Fork：2.26 起用 Workspaces 组织多仓；2.71 每个窗口独立一个 Workspace，⌘ 点击在新窗口打开；标签页徽标提示未提交改动（2.45），标签可重命名、着色、在终端打开（2.68），⇧⌘T 恢复关闭的标签（2.67）；新仓库自动出现在仓库管理器（2.56）。

## 4. 交互规格

### 4.1 工作区切换（F01）

入口：标题栏工作区 pill；菜单「文件 > 工作区」；命令面板「切换工作区」。

```text
+-- 工作区 ------------------------------------------+
| (*) 抖音 iOS 组件       52 仓   今天 10:12 打开     |
| ( ) 抖音 Android        31 仓   昨天                |
| ( ) 后端服务            8 仓    10-27               |
+----------------------------------------------------+
| + 新建工作区...   复制   重命名   删除              |
| 按住 ⌘ 点击：在新窗口打开                          |
+----------------------------------------------------+
```

- 新建工作区提供三种来源：空工作区、扫描父目录、导入 mgit 清单。
- 删除只删工作区配置，不碰磁盘上的仓库；确认文案写明「仓库文件不会被删除」。
- 同一工作区不允许在两个窗口同时打开，再次打开时聚焦已有窗口。

### 4.2 窗口与标签页（F02）

- 使用 macOS 原生窗口标签。每个窗口绑定一个工作区，第一个标签固定是「工作区」视图（现有五视图）。
- 侧栏仓库行右键「在新标签打开」，打开单仓视图：时间线、提交、分支只针对这个仓，侧栏显示该仓的分支树（EP06-F01）。
- 标签标题显示仓库名，名称相同时附加第一个不同的路径段（Fork 2.58）；有未提交改动时显示数字徽标。
- 标签右键：重命名、选择颜色、在终端打开、在访达显示、关闭其他标签。
- 关闭的标签可用 ⇧⌘T 恢复；重启后恢复上次的窗口、标签与选中项。

| 状态 | 表现 |
|---|---|
| 仓库被移出工作区 | 对应标签显示「仓库已移除」空态，提供「关闭标签」 |
| 仓库路径不存在 | 标签与侧栏都标记「读取失败」，提供「重新定位 / 移除」 |
| 单仓标签中仓库合并进行中 | 标签与工作区视图同时显示合并横幅 |

### 4.3 鉴权失败与凭据（F03）

- 批量结果、单仓同步、Push 对话框中，鉴权类失败（`GitError` 鉴权分类）都显示「配置凭据」按钮。
- HTTPS remote：输入用户名与 token，经 `git credential approve` 交给系统凭据助手（osxkeychain）保存；GitSpace 自身不落盘、不写日志。
- SSH remote：显示 `ssh-add -l` 结果与对目标主机的连通性检查结果，给出 `~/.ssh/config` 的打开入口；不自建 SSH 栈。
- 方案待评审：TechStack §8 写的是 Security framework 直写 Keychain；本文建议走 git credential，保证 CLI 与 GitSpace 读到同一份凭据。

### 4.4 分组与新仓库发现（F04、F05）

- 侧栏支持三种分组：按父目录、按自定义组（拖拽归组）、按状态（有改动 / 待推送 / 落后 / 干净）；收藏的仓库置顶。
- 工作区根目录下新出现 Git 仓库时，侧栏顶部出现提示条：「发现 3 个未纳管仓库 [查看并添加] [忽略]」；忽略的路径写入工作区配置，之后不再提示。

### 4.5 Remote 管理（F06）

- 入口：仓库行右键「管理 Remote」。表格列出 name、fetch URL、push URL，支持新增、重命名、删除（二次确认）、改 URL、「测试连接」（`git ls-remote --heads <remote>`，只读）。

## 5. 验收口径

1. 工作区配置的新建、复制、删除前后，各仓 `git status --porcelain` 与磁盘文件不变。
2. 标签徽标数字与该仓 `git status --porcelain` 的条目数一致。
3. 重启后窗口、标签、工作区与选中仓库按关闭前恢复。
4. 凭据保存后，命令行 `git fetch` 在同一 remote 上不再要求输入凭据；GitSpace 的日志与配置文件中搜不到 token。
5. Remote 增删改的结果与 `git remote -v` 一致。

## 6. 风险与明确不做

- 不做账号体系与云端同步（MRD 10.5）。工作区共享只做文件导出导入。
- 不在 GitSpace 内保存任何明文凭据。
- 批量克隆会产生大量网络请求，复用 EP05-F01 的并发与超时设置。
